# План: WhatsApp-чат через Wappi

Цель — чтобы клиенты писали магазину в WhatsApp, а бот и менеджер отвечали так же, как в Telegram:
ИИ-бот (поиск товаров, торг не ниже `min_price`, заявка через `create_order`, передача менеджеру),
переписка — в разделе «Чаты» админки, уведомления — в приложениях.

Статус: **сделано 2026-11-23** (см. docs/PROGRESS.md); ниже — исходный план. Сверено с https://wappi.pro/api-documentation (ноябрь 2026). Пункты с пометкой
«проверить» в документации описаны неполно — уточняем тестовым запросом на пробном периоде.

## Что такое Wappi

- Сервис-посредник: подключает обычный WhatsApp-номер (как WhatsApp Web, по QR-коду) и даёт HTTP API.
  Это не официальный WhatsApp Business API от Meta — проще и дешевле, но есть риск блокировки номера
  за спам. Поэтому: **отдельный номер магазина**, никаких рассылок, отвечаем только тем, кто написал сам.
- Цена: тариф «Базовый» — 700 ₽/мес за один номер (дешевле при оплате на 3/6/12 мес), сообщения без лимита.
  Пробный период — 5 дней.
- Один «профиль» Wappi = один подключённый номер WhatsApp, у него свой `profile_id`.

## API, которое понадобится

- Авторизация: заголовок `Authorization: <токен>` (без «Bearer»), в каждом запросе `?profile_id=...`.
- Отправить текст: `POST https://wappi.pro/api/sync/message/send?profile_id=...`,
  тело `{ "recipient": "79991234567", "body": "текст" }` или `{ "chat_id": "...@c.us", ... }`.
  Номер — с кодом страны, без «+» и без 8 в начале.
- Отправить фото товара: `POST /api/sync/message/file/url/send` — `{ recipient | chat_id, url, caption }`.
- Голос в ответ: `POST /api/sync/message/audio/send` (файл в base64) — **проверить**, как он показывается у клиента.
- Входящие — вебхук на наш URL: `POST /api/webhook/url/set?profile_id=...&url=...` (есть параметр `auth` —
  секрет, **проверить**, как он приходит обратно). Типы событий — `POST /api/webhook/types/set`,
  нужен `incoming_message` (+ `authorization_status`, чтобы знать, что номер отвалился).
- Входящее сообщение: `wh_type: "incoming_message"`, `from`/`chatId` (`79991234567@c.us`), `senderName`,
  `type` (`chat` — текст, `ptt` — голосовое, `image`, ...), `body` (текст или файл в base64), `mimetype`.
- Состояние номера: `GET /api/sync/get/status?profile_id=...` (`authorized`, `phone`, `payment_expired_at`).
  QR для входа: `GET /api/sync/qr/get?profile_id=...` (картинка base64).

## Как встроить в проект

1. **База (миграция).** Не заводим отдельные таблицы: в `bot_chats` добавляем канал
   `channel text not null default 'telegram' check (channel in ('telegram','whatsapp'))` и
   `whatsapp_chat_id text` (уникальный, вместо `telegram_chat_id` для WhatsApp; `telegram_chat_id`
   становится необязательным). `bot_messages` без изменений. У `orders.source` добавить `'whatsapp'`.
   В `bot_settings` — `whatsapp_enabled`, последние 4 символа токена для показа, `whatsapp_profile_id`.
2. **Секреты.** Токен Wappi — в Supabase Vault (как токен Telegram): RPC `wappi_token_set/get/clear`,
   только `service_role`. Во фронтенд токен не возвращается. Секрет вебхука — тоже в Vault.
3. **Edge Function `whatsapp-webhook`.** Принимает событие Wappi → проверяет секрет → находит/создаёт чат
   (`channel = 'whatsapp'`) → пишет сообщение клиента → если чат у бота, вызывает тот же
   `_shared/botAi.ts` → отправляет ответ через Wappi. Голосовое (`ptt`, base64) → распознавание
   через `_shared/voice.ts`, как в Telegram. При сбое ИИ — чат уходит менеджеру.
4. **Общий слой «канал».** Вынести отправку из `telegram-webhook` в `_shared/channels.ts`:
   `sendText(chat, text)`, `sendPhoto(chat, url, caption)`, `sendVoice(chat, audio)` с реализациями
   для Telegram и WhatsApp. `botAi.ts` о канале не знает.
5. **Edge Function `whatsapp-admin`** (или новые действия в `telegram-admin`): сохранить токен и `profile_id`,
   проверить статус, показать QR, включить вебхук, ответ менеджера в WhatsApp-чат.
6. **Админка.**
   - «Настройки» → раздел «WhatsApp (Wappi)»: токен, `profile_id`, статус номера, QR при необходимости,
     кнопка «Проверить», дата окончания оплаты (`payment_expired_at`) с предупреждением заранее.
   - «Чаты»: значок канала (Telegram / WhatsApp) и фильтр по каналу; ответ менеджера уходит в нужный канал.
   - Уведомления в приложениях уже работают для всех чатов (`bot_chats`/`bot_messages`) — ничего не меняем.
7. **Сайт.** Кнопка WhatsApp в подвале уже есть (номер из «Магазин и контакты») — она и приведёт клиента в этот чат.
8. **Проверка.** Локально: вебхук с примерами входящих событий (текст, голосовое, фото), ответы бота,
   передача менеджеру, ответ менеджера. Затем пробный период Wappi на настоящем номере.

## Что нужно от владельца

1. Отдельный номер телефона для WhatsApp магазина (лучше WhatsApp Business на отдельном телефоне).
2. Регистрация на wappi.pro, создание профиля, вход по QR с этого номера (пробные 5 дней бесплатно).
3. Токен и `profile_id` — вставить самим в «Настройки» → «WhatsApp» (мне их не присылать).
4. Оплата тарифа после проверки (от 550–700 ₽/мес).

## Оценка

Миграция + общий слой каналов + 2 функции + раздел настроек + доработка «Чатов»: примерно один рабочий
день разработки и полдня на проверку с настоящим номером.

## Риски

- Неофициальный протокол WhatsApp Web: возможна блокировка номера при жалобах/спаме, Wappi может временно
  не работать при изменениях WhatsApp. Telegram-бот остаётся основным каналом.
- Файлы во входящих приходят в base64 — большие фото/видео тяжёлые; храним только текст и распознанный голос,
  фото клиента — позже, через R2.
- Окончание оплаты Wappi = бот молча перестаёт отвечать → предупреждение в админке и в Telegram-группе.
