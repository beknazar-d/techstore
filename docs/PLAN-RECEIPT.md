# План: электронный чек (подтверждение заказа) для клиента

Статус: **план, не начато** (просьба владельца 2026-11-24).

## Что видит клиент

Электронный документ по заявке:
- номер заявки и дата/время оформления;
- товар (название, состояние для Б/У), количество, цена за штуку, **сумма покупки**;
- способ получения и **адрес** доставки (или адрес магазина для самовывоза), желаемые дата и время;
- имя и телефон клиента;
- «Оплата при получении», контакты и название магазина (`shop_settings`).

Это **не фискальный чек**: онлайн-оплаты нет, деньги клиент отдаёт на месте — фискальный чек выдаёт касса
магазина при оплате. Документ называется «Подтверждение заказа» / «Электронный чек заявки» (уточнить у владельца).

## Как доставить клиенту

1. **Страница по ссылке** `/order/<token>` — открывается без входа, по случайному токену (номер заказа угадывается,
   токен — нет). Кнопки «Сохранить PDF / Распечатать» (печать браузера, без библиотек).
2. **Сайт:** после заявки на экране «Заявка №… принята» — кнопка «Открыть чек».
3. **Telegram / WhatsApp:** если заявку оформил бот — сразу после оформления бот присылает сводку и ссылку на чек.
4. (Потом, если нужно) SMS — платно, отдельный сервис.

## Как встроить

- Миграция: `orders.receipt_token uuid default gen_random_uuid()` (уникальный); RPC `get_order_receipt(p_token)` —
  security definer, отдаёт только поля чека (без `admin_note`, `cost_price` и т. п.), доступна anon.
- `create_order` возвращает ещё и токен → сайт и бот строят ссылку.
- Страница `src/pages/ReceiptPage.tsx` (+ CSS-модуль, стили печати `@media print`), тексты ru/ky.
- Статус заказа на чеке (новая / подтверждена / выполнена / отменена) — клиент видит актуальное состояние.

## Вопросы владельцу

- Показывать ли статус заказа на чеке.
- Нужна ли SMS-отправка.
